1. mantiqz/ vs mantiq/ — The Bootstrap Pipeline
From readme.md:
mantiqz/ is a Zig bootstrap of the Mantiq/Nizam languages.  
mantiq/ is the self-hosted language, compiled using the Zig bootstrap.
mantiqz/ (the bootstrap — written in Zig):
mantiqz/

    zig-out/bin/

      nizam              # Compiled bootstrap compiler binary

mantiq/ (the self-hosted compiler — written in Mantiq/Nizam itself):

  std/                    # Standard library (.nz + .ll files)

The bootstrap pipeline is:
1. Build the Zig bootstrap: cd mantiqz/mantiq-compiler && zig build → produces mantiq and nizam binaries
2. Use the bootstrap to compile the self-hosted compiler: ./nizam build mantiq/src/main.nz -o mantiq/src/ast → produces the ast ELF binary (the stage-1 self-hosted compiler)
3. The self-hosted compiler (ast) can then compile other .nz/.mq files using ./ast build file.nz -o output
2. Zig Bootstrap (mantiqz/mantiq-compiler/) — Build Details
build.zig.zon
- Package name: mantiq-compiler, version 0.0.0
- No external dependencies declared (all deps are system-level: tree-sitter C lib, mimalloc, pthread)
- Fingerprint: 0xfbd19caefc2f0205
build.zig — Key Behavior
Builds three artifacts:
1. Static library libmantiq-compiler.a from src/root.zig (trivial stub, just an add function)
2. Executable mantiq from src/main.zig
3. Executable nizam from src/main.zig (same source, different name)
Linking strategy for executables (via ExeConfig.configure):
1. Adds ../tree-sitter-mantiq/src/parser.c and ../tree-sitter-mantiq/src/scanner.c as C source files (tree-sitter generated parser)
2. Finds the tree-sitter C library (libtree-sitter.a/.so) from either:
- A --tree-sitter-dir CLI option, OR
- $HOME/.cargo/registry/src/index.crates.io-*/tree-sitter-0.26.7/ (looks in Cargo registry)
3. Links that tree-sitter C library's src/lib.c (the core tree-sitter runtime)
4. Adds include paths for tree-sitter's include/ and src/ directories plus ../tree-sitter-mantiq/src/
5. Calls linkLibC() (links libc)
No mimalloc or pthread at link time in the build.zig — those are only added at runtime by the AOT/JIT backends when they invoke zig cc.
3. Where Does libtree-sitter-mantiq.so Come From?
It is NOT built by the Zig build system. There is no build script (no Makefile, no CMakeLists.txt, no .sh) in the entire project.
The libtree-sitter-mantiq.so is the tree-sitter mantiq parser compiled as a shared library. It is built from the files in tree-sitter-mantiq/src/:
tree-sitter-mantiq/src/
  parser.c           # Auto-generated by tree-sitter from grammar.js (~432K lines)
  scanner.c          # External scanner (handles custom tokens)
  grammar.json       # Compiled grammar definition
  node-types.json    # Node type metadata
  tree_sitter/
    parser.h         # tree-sitter C API header
    array.h          # Internal array data structure
    alloc.h          # Memory allocation macros
To build it yourself: You would compile these into a shared object:
cc -shared -fPIC -O2 \
  src/parser.c src/scanner.c \
  -o libtree-sitter-mantiq.so
The Zig bootstrap does NOT use this .so — it links parser.c and scanner.c statically into the zig compiler binary itself. The .so is only used by the self-hosted compiler (mantiq/src/main.nz), which calls dlopen("libtree-sitter-mantiq.so") via the link "tree-sitter-mantiq" declaration in tree_sitter.nz.
The same .so file appears in both mantiq/libtree-sitter-mantiq.so and mantiq/src/libtree-sitter-mantiq.so (they are identical, same build ID).

6. tree_sitter_helper.c — Location and Purpose
There are two copies of this file:
1. /home/red-x/projects/desktop/mantiq_nizam/mantiq/tree_sitter_helper.c (57 lines)
2. /home/red-x/projects/desktop/mantiq_nizam/mantiq/src/tree_sitter_helper.c (same content, duplicate)
Purpose: The tree-sitter C API uses pass-by-value for TSNode structs. However, the self-hosted compiler's Nizam FFI only supports pass-by-pointer for structs. tree_sitter_helper.c provides wrapper functions that accept TSNode* and delegate to the real tree-sitter API, e.g.:
- ts_tree_root_node_ptr(tree, &out_node) — wraps ts_tree_root_node()
- ts_node_type_ptr(&node) — wraps ts_node_type()
- ts_node_child_ptr(&node, index, &out_node) — wraps ts_node_child()
- etc.
This file is compiled and linked into the final binary alongside the generated LLVM IR and the runtime C code.
7. How compile_source() Links the Final Binary
In mantiq/src/main.nz (lines 54-93), the compile_source function works as follows:
Pipeline:
1. Parse: Creates a Lowerer from source C string via make_lowerer_mantiq_from_cstr(), calls lower_source() to get the AST root
2. Semantic analysis: Runs sema.declare_pass() then sema.resolve_pass()
3. Type checking: tc.typecheck_node(root)
4. Borrow checking: bc.walk_ast(root)
5. Codegen: cg.generate(root) → returns LLVM IR as a String
6. Write IR to file: Writes IR to /tmp/mantiq_tmp.ll
7. Compile and link:
The linking command (line 91):
sprintf(cmd_buf,
  "zig cc -O2 /tmp/mantiq_tmp.ll -L. -ltree-sitter-mantiq tree_sitter_helper.c -o %s 2>&1 "
  "|| gcc -O2 /tmp/mantiq_tmp.ll -L. -ltree-sitter-mantiq tree_sitter_helper.c -o %s 2>&1 "
  "|| clang -O2 /tmp/mantiq_tmp.ll -L. -ltree-sitter-mantiq tree_sitter_helper.c -o %s 2>&1",
  out_file, out_file, out_file);
This means:
1. It tries three compilers in order: zig cc, then gcc, then clang
2. Inputs:
- /tmp/mantiq_tmp.ll — the generated LLVM IR
- tree_sitter_helper.c — the C wrapper (linked as a source file)
3. Link flags:
- -L. — look for libraries in current directory
- -ltree-sitter-mantiq — link against libtree-sitter-mantiq.so
- -o <out_file> — output binary
4. The tree-sitter runtime functions are resolved from the shared library
5. The LLVM IR references runtime functions (like mantiq_malloc, mantiq_print_*, etc.) which are expected to be available at link time — these are declared as extern in the generated LLVM IR (visible in string.ll)
Runtime dependencies:
The final binary depends on:
- libtree-sitter-mantiq.so — for parsing (loaded at runtime by the compiler itself)
- libmimalloc (optional, for the JIT runtime -lmimalloc in jit.zig)
- pthread (for async/concurrency runtime)
Bootstrap compiler's AOT path (aot.zig):
The Zig bootstrap's AOT backend does essentially the same thing but more robustly:
- Writes IR to <name>.ll
- Writes embedded runtime.c to <name>_runtime.c
- Invokes zig cc <name>.ll <name>_runtime.c -O2 -o <name>
- Collects link targets from AST and passes them as -l<lib> flags
Summary of all inputs needed for a build script:
To compile a .nz file with the self-hosted compiler:
- libtree-sitter-mantiq.so (must be in the current directory, -L.)
- tree_sitter_helper.c (compiled alongside the IR)
- The generated LLVM IR file
- A C compiler (zig cc, gcc, or clang)
To compile the self-hosted compiler itself:
1. Generate LLVM IR from main.nz using the bootstrap compiler
2. Link with zig cc / gcc / clang, passing -ltree-sitter-mantiq -L. and tree_sitter_helper.c
3. The resulting binary (ast) is the stage-1 self-hosted compiler
To build libtree-sitter-mantiq.so from scratch:
cc -shared -fPIC -O2 \
  src/parser.c src/scanner.c \
  -o libtree-sitter-mantiq.so
(Using the files from either mantiq/tree-sitter-mantiq/src/ or mantiqz/tree-sitter-mantiq/src/)
